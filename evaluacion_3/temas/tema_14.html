Clases y objetos: modelar con programación orientada a objetos

Cuando el programa crece, los datos y su comportamiento piden viajar juntos. Las clases permiten modelar las entidades del problema tal como son.

  • 6–7 sesiones
  • Prácticas de la evaluación
  • 1 evaluación Moodle
  • Trabajo en el aula

Al terminar podrás:

  • detectar cuándo conviene agrupar datos sueltos en una clase;
  • definir clases con atributos, métodos y una representación legible;
  • proteger el estado interno del objeto con la encapsulación básica;
  • crear objetos que colaboran y clases que reutilizan código con herencia.

Pregunta guía
En el instituto, ¿qué «cosas» tienen datos (nombre, curso, notas) y comportamiento (matricularse, aprobar)? ¿Cómo agruparías cada cosa con lo que puede hacer?
01 / MODELAR

De las funciones sueltas a las clases

Con funciones y listas, los datos de cada entidad viajan en listas paralelas: la posición 3 de una corresponde a la 3 de la otra. Funciona, pero se rompe al añadir un dato: los datos van separados de lo que se hace con ellos.

# Varias listas paralelas: frágil al crecer
titulos = ["Dune", "Neuromante"]
anios = [1965, 1984]

def info_libro(i):
    return f"{titulos[i]} ({anios[i]})"

print(info_libro(1))    # Neuromante (1984)

La programación orientada a objetos agrupa en una clase los datos (atributos) y el comportamiento (métodos) de una entidad del problema: un libro, un préstamo, un pedido. De la clase se crean objetos, cada uno con sus valores.

Idea claveSi llevas listas paralelas cuyas posiciones deben coincidir siempre, es la señal clásica de que ahí falta una clase.
02 / CLASES

Tu primera clase: atributos y métodos

__init__ crea el objeto y guarda los valores iniciales como atributos con self.. Los métodos son funciones que actúan sobre el objeto; __str__ decide qué se muestra al imprimirlo.

class Rectangulo:
    """Figura rectangular con ancho y alto en centímetros."""

    def __init__(self, ancho, alto):
        self.ancho = ancho      # atributos: datos del objeto
        self.alto = alto

    def area(self):             # métodos: comportamiento
        return self.ancho * self.alto

    def __str__(self):
        return f"Rectángulo {self.ancho} x {self.alto} cm"

# Pruebas (ancho 4, alto 3): area()->12 · str()->'Rectángulo 4 x 3 cm'

self es el propio objeto: permite que cada rectángulo calcule con sus medidas. Dos Rectangulo(4, 3) con los mismos datos no son el mismo objeto: == no los iguala, habría que comparar atributo a atributo.

03 / CONTROL

El objeto controla su estado: encapsulación

Un saldo no debería poder volverse negativo por un descuido. La encapsulación dice que el objeto es dueño de su estado: los cambios pasan por sus métodos, que aplican las reglas. En Python se marca con un guion bajo: _saldo = «interno». Es una convención, no un candado.

class Cuenta:
    """Cuenta bancaria sencilla; el saldo vive en un atributo interno."""

    def __init__(self, titular, saldo_inicial=0):
        self.titular = titular
        self._saldo = saldo_inicial

    def ingresar(self, cantidad):
        if cantidad <= 0:
            return False            # solo cantidades positivas
        self._saldo += cantidad
        return True

    def retirar(self, cantidad):
        if cantidad <= 0 or cantidad > self._saldo:
            return False            # nada de números rojos
        self._saldo -= cantidad
        return True

# Pruebas: retirar(150) con saldo 100 -> False · ingresar(-5) -> False

El método devuelve False cuando la operación no se puede hacer, en lugar de dejar el objeto en un estado imposible: las reglas viven dentro de la clase.

Idea claveEl guion bajo avisa de que un atributo es interno; los métodos validan antes de cambiar el estado.
04 / OBJETOS

Objetos que colaboran entre sí

Los programas reales crean colecciones de objetos que se llaman entre sí: un objeto puede tener como atributo una lista de objetos, así se modela «una playlist contiene canciones».

class Cancion:
    def __init__(self, titulo, duracion_s):
        self.titulo = titulo
        self.duracion_s = duracion_s

class Playlist:
    def __init__(self, nombre):
        self.nombre = nombre
        self.canciones = []        # un objeto contiene una lista de objetos

    def agregar(self, cancion):
        self.canciones.append(cancion)

    def duracion_total(self):
        return sum(c.duracion_s for c in self.canciones)

# Pruebas: dos canciones de 180 y 240 s -> 420 · playlist vacía -> 0

sum([]) devuelve 0, así que la playlist vacía no rompe nada: preguntar siempre «¿qué hace mi objeto con la colección vacía?» separa el diseño sólido del que falla en producción. (Se prueba con el conjunto vacío.)

05 / REUSO

Clases que heredan de otras

Cuando dos clases comparten comportamiento —un círculo y un rectángulo son figuras, ambas con color y área— la herencia evita repetir: la hija recibe lo de la madre y añade o cambia lo suyo. super().__init__(...) llama al constructor de la madre.

class Figura:
    def __init__(self, color):
        self.color = color

    def area(self):
        raise NotImplementedError("cada figura implementa su área")

class Circulo(Figura):
    def __init__(self, color, radio):
        super().__init__(color)     # reutiliza el constructor de Figura
        self.radio = radio

    def area(self):
        return 3.1416 * self.radio ** 2

# Pruebas: Circulo("rojo", 2).area() -> 12.5664 · .color -> 'rojo' (heredado)

raise NotImplementedError convierte la clase madre en un plano incompleto: «esto lo decide cada figura». Usa la herencia con moderación: para compartir una sola función, mejor ponerla fuera.

06 / SALIDA

Lo esencial

  1. Si llevas listas paralelas cuyos índices deben coincidir, es hora de agrupar esos datos en una clase.
  2. __init__ crea el objeto y guarda atributos con self.; los métodos actúan sobre el objeto.
  3. __str__ decide cómo se imprime el objeto; dos objetos con los mismos datos no son el mismo objeto.
  4. La encapsulación (atributos con _ y métodos que validan) mantiene el estado siempre coherente.
  5. Los objetos se guardan en listas y se llaman entre sí; la herencia reutiliza lo común con super().
